1. PROJECT OVERVIEW & PROBLEM STATEMENT
================================================================================

PROJECT NAME: Flocksy (PoultryCare AI)
TAGLINE: "AI-Powered Poultry Intelligence — See Disease Before It Spreads"

WHAT IS FLOCKSY?
Flocksy is an AI-powered poultry farm intelligence platform that combines
computer vision (CNN-based disease detection), multi-agent AI orchestration,
and verified veterinary knowledge to provide real-time flock health diagnostics,
treatment guidance, feed optimization, and environmental management.

THE PROBLEM WE SOLVE:
 • India has 30B+ poultry birds — yet most farmers lack access to veterinarians
 • Poultry diseases (Coccidiosis, Newcastle, Salmonella) spread in HOURS,
   killing entire flocks before a vet can arrive
 • Existing farm apps are generic — they don't analyze images or contextualize
   by flock age, environment, or feed history
 • Farmers self-medicate birds with antibiotics, creating drug-resistant strains
   and violating food-safety withdrawal periods
 • No platform combines image-based disease detection with environment-aware
   treatment guidance using verified veterinary datasets
 • Farm data (mortality, feed costs, treatment history) is scattered in notebooks

WHO IS IT FOR?
 • Poultry farmers managing broiler/layer flocks of any size
 • Farm managers overseeing multiple poultry houses
 • Veterinarians who need AI-assisted remote triage
 • Agricultural researchers studying disease patterns
 • Government bodies monitoring disease outbreaks

WHAT WE DO NOT DO (Critical Safety Boundary):
 ✗ We do NOT replace licensed veterinarians
 ✗ We do NOT guarantee diagnosis accuracy — always confirm clinically
 ✗ We do NOT prescribe controlled substances
 ✗ We ALWAYS recommend professional consultation for high-mortality events

2. SOLUTION & USP (Unique Selling Points)
================================================================================

OUR SOLUTION:
A multi-agent AI system that:
 1. Detects disease from fecal/bird images using a custom-trained CNN model
 2. Cross-references symptoms with a verified disease database (MCP)
 3. Recommends medicines with dosage, route, and withdrawal periods
 4. Optimizes feed plans based on flock age and stress levels
 5. Evaluates housing environment (temperature, humidity, ventilation)
 6. Validates ALL recommendations through a Safety Agent before delivery

USPs (What Makes Us Different):

 USP 1: Computer Vision Disease Detection (Custom CNN)
   → A 4-layer Convolutional Neural Network trained on real poultry disease
     images (fecal samples, bird carcasses). Classifies diseases like
     Coccidiosis, Newcastle Disease, Salmonellosis, and Healthy flocks.
   → Not just text — farmers can UPLOAD A PHOTO and get instant analysis.

 USP 2: Agent-to-Agent (A2A) Architecture
   → Five specialized agents + one orchestrator collaborate:
     Disease Agent, Medicine Agent, Feed Agent, Environment Agent,
     Safety Agent, and the Orchestrator. Each is an expert in one domain.

 USP 3: Model Context Protocol (MCP) — 6 Microservices
   → AI never touches databases directly. Six independent MCP services
     fetch ONLY verified data from curated JSON datasets.
   → Disease MCP, Medicine MCP, Feed MCP, Environment MCP, Safety MCP,
     Memory MCP — each with strict input/output schemas.

 USP 4: RAG-Grounded Knowledge
   → Veterinary knowledge from FAO, ICAR, and reference handbooks is
     chunked, embedded, and searched at query time. AI cites sources.

 USP 5: Safety-First Architecture
   → A dedicated Safety Agent + Safety MCP validates EVERY recommendation.
     Contraindicated treatments are flagged. Young-flock dosage alerts
     are triggered automatically. Withdrawal periods are enforced.

 USP 6: Real-Time Farm Context
   → Every analysis considers: flock age, temperature, humidity, feed type,
     batch history. Not generic advice — personalized to YOUR farm TODAY.

6. CORE CONCEPTS — EXPLAINED SIMPLY
================================================================================

WHAT IS AN LLM?
An LLM (Large Language Model) is like a brilliant veterinary textbook that can
TALK. It has read millions of papers. But it has NO hands — it cannot open
files, search databases, check your farm records, or look at your bird photos.

What LLM does:     Thinks, reasons, generates text, summarizes symptoms
What LLM does NOT: Fetch data, access databases, analyze images, verify facts

WHAT IS MCP (Model Context Protocol)?
MCP is like a FILING CLERK at a veterinary clinic.

Analogy:
 • The Vet (AI Agent) says: "I need the treatment protocol for Coccidiosis"
 • The Filing Clerk (MCP) goes to the medicine cabinet (database), pulls the
   record, and hands it to the vet
 • The Filing Clerk does NOT interpret the record, does NOT give medical advice

MCP is:
 ✓ A small backend API microservice (FastAPI)
 ✓ Has strict input/output schemas
 ✓ Returns ONLY verified data from curated JSON datasets
 ✓ Responds ONLY to requests from the AI Core

MCP is NOT:
 ✗ Not an AI (it does NOT think or reason)
 ✗ Not a database (it READS from data files, it IS NOT the data)
 ✗ Not a learner (it does NOT improve over time)
 ✗ Not a user interface (it does NOT talk to farmers)

WHY DATABASES SHOULD NEVER BE ACCESSED DIRECTLY BY THE LLM:
 • If the LLM had direct database access, it could:
   - Read ALL farm data (privacy violation)
   - Write incorrect data (hallucination stored as fact)
   - Execute dangerous queries (prompt injection → SQL injection)
 • MCP acts as a FIREWALL between the AI and your data

WHY SEPARATION OF CONCERNS IS CRITICAL:
 • Safety: Each component has ONE job. Fewer ways to break.
 • Debugging: If medicine is wrong, check Medicine MCP — not entire system.
 • Scalability: Upgrade the LLM without touching any MCP.
 • Compliance: Food safety regulations require auditable data access.

7. AI AGENTS (A2A SYSTEM) — WHO DOES WHAT
================================================================================

The A2A (Agent-to-Agent) architecture means five specialized agents + one
orchestrator collaborate to produce a final recommendation.

AGENT 1: DISEASE AGENT
 • Job: Identifies the most likely poultry disease
 • Input: CNN vision result + Disease MCP data + symptom summary
 • Output: Disease prediction with confidence score
 • Data calls: Uses Disease MCP search results (pre-fetched by orchestrator)
 • Analogy: The lab technician who reads test results

AGENT 2: MEDICINE AGENT
 • Job: Recommends treatment protocol for the identified disease
 • Input: Medicine MCP recommendation data
 • Output: Medicine name, dosage, route, frequency, withdrawal period
 • Data calls: Uses Medicine MCP results (pre-fetched by orchestrator)
 • Analogy: The pharmacist who dispenses the right drug

AGENT 3: FEED AGENT
 • Job: Optimizes nutritional strategy for the flock's current state
 • Input: Farm context (age, stress) + Feed MCP profile
 • Output: Feed type, protein %, energy kcal, additives
 • Data calls: Uses Feed MCP results (pre-fetched by orchestrator)
 • Analogy: The nutritionist who adjusts the diet plan

AGENT 4: ENVIRONMENT AGENT
 • Job: Evaluates housing conditions against age-specific thresholds
 • Input: Environment MCP recommendation + climate warnings
 • Output: Temperature range, humidity target, ventilation advice
 • Data calls: Uses Environment MCP results (pre-fetched by orchestrator)
 • Analogy: The farm inspector checking the poultry house

AGENT 5: SAFETY AGENT
 • Job: VALIDATES all recommendations before they reach the farmer
 • Input: Safety MCP flags + Medicine Agent payload
 • Output: Approved/blocked status + warning flags
 • Data calls: Uses Safety MCP validation results
 • CRITICAL: Enforces withdrawal periods, flags young-flock risks
 • ALWAYS runs last, NEVER skipped
 • Analogy: The chief veterinarian who signs off on every prescription

AGENT 6: ORCHESTRATOR (Master Controller)
 • Job: Coordinates ALL agents, fetches ALL MCP data, builds final report
 • Input: Farmer's original request (symptoms + image + farm context)
 • Output: Complete FinalRecommendation with all sections + warnings
 • Sequence:
   1. Runs CNN vision prediction on uploaded image
   2. Summarizes symptoms via LLM
   3. Fetches data from ALL 6 MCPs in parallel
   4. Passes data to each specialized agent
   5. Collects all agent insights
   6. Computes accuracy (mean confidence)
   7. Builds detailed analysis report with safety warnings
   8. Returns structured JSON response

HOW AGENTS TALK (Data Flow):
 1. Farmer submits: "My birds have bloody droppings, age 21 days" + image
 2. Orchestrator → CNN Vision → "Coccidiosis (84% confidence)"
 3. Orchestrator → Disease MCP → confirms symptoms match Coccidiosis
 4. Orchestrator → Medicine MCP → "Amprolium, 10mg/kg, 5 days"
 5. Orchestrator → Feed MCP → "Grower feed, 20% protein, electrolytes"
 6. Orchestrator → Environment MCP → "Keep 24°C, reduce humidity"
 7. Orchestrator → Safety MCP → checks for contraindications
 8. Orchestrator → Memory MCP → checks farm's incident history
 9. Orchestrator → RAG → searches veterinary knowledge base
 10. Disease Agent → produces disease insight
 11. Medicine Agent → produces treatment insight
 12. Feed Agent → produces nutrition insight
 13. Environment Agent → produces climate insight
 14. Safety Agent → validates everything, adds withdrawal warnings
 15. Orchestrator → combines ALL insights → FinalRecommendation → Farmer

KEY RULE: Agents REASON using data fetched by the Orchestrator via MCPs.
Agents never directly access databases or external services.

8. WHAT MCP ACTUALLY IS (Detailed)
================================================================================

Think of MCP as a VENDING MACHINE:
 • You press a button (send a request with specific parameters)
 • It gives you exactly what you asked for (structured JSON data)
 • It doesn't think about what you need
 • It doesn't remember what you asked before
 • It doesn't give you things you didn't ask for

TECHNICAL DEFINITION:
MCP is a lightweight backend API microservice (Python FastAPI) that:
 • Exposes a fixed set of endpoints (GET /search, GET /recommend, POST /validate)
 • Has strict input schema (query parameters or JSON body)
 • Has strict output schema (JSON response)
 • Reads from a specific JSON data file (curated veterinary dataset)
 • Returns ONLY verified, structured data
 • Has NO AI, NO reasoning, NO learning capability

WHAT MCP DOES:
 ✓ Receives a structured HTTP request from the AI Core
 ✓ Validates the input against its schema
 ✓ Queries its designated JSON data file
 ✓ Returns structured data (JSON response)
 ✓ Logs the request for audit purposes

WHAT MCP DOES NOT DO:
 ✗ Does NOT think or reason
 ✗ Does NOT learn or improve
 ✗ Does NOT store AI-generated answers
 ✗ Does NOT talk to farmers directly
 ✗ Does NOT access data outside its scope
 ✗ Does NOT modify data based on AI output

9. MCPs BUILT (Detailed Breakdown)
================================================================================

MCP 1: DISEASE MCP (Port 8101)
  File: mcp-services/disease_mcp/app/main.py
  Data: mcp-services/disease_mcp/data/diseases.json

  Endpoint:  GET /search?query={text}&symptoms={text}
  Logic:     Combines query+symptoms into lowercase string, searches diseases.json
             for matching disease name or any matching symptom keyword.
  Returns:   { "match": {...disease_object}, "items": [...all_diseases] }

  Data Schema (diseases.json — each record):
    {
      "disease": "Coccidiosis",
      "symptoms": ["bloody droppings", "lethargy", "ruffled feathers"],
      "cause": "Eimeria protozoan parasites",
      "mortality_rate": "20-50%",
      "transmission": "Fecal-oral, contaminated litter",
      "incubation_days": 4-7,
      "affected_age_group": "2-8 weeks"
    }

  Key Design Decisions:
   • Text-based matching (not AI) — deterministic, auditable
   • Returns ALL diseases alongside match for context
   • No write operations — read-only verified data

MCP 2: MEDICINE MCP (Port 8102)
  File: mcp-services/medicine_mcp/app/main.py
  Data: mcp-services/medicine_mcp/data/medicines.json

  Endpoint:  GET /recommend?disease={text}
  Logic:     Searches medicines where the disease name appears in the
             medicine's "used_for" array.
  Returns:   { "recommendation": {...medicine_object} }

  Data Schema (medicines.json — each record):
    {
      "name": "Amprolium",
      "type": "Anticoccidial",
      "used_for": ["Coccidiosis"],
      "dosage": "10 mg/kg body weight",
      "route": "Drinking water",
      "duration_days": 5,
      "withdrawal_period_days": 1,

11. RAG SYSTEM (Retrieval-Augmented Generation)
================================================================================

WHAT IS RAG?
RAG = Retrieval-Augmented Generation. Instead of relying on the LLM's training
data alone, we SEARCH our own verified veterinary knowledge base and feed the
relevant chunks into the AI's prompt. This grounds the AI in factual data.

WHY RAG?
 • LLMs can hallucinate — RAG forces citation of verified sources
 • Veterinary knowledge updates faster than LLM retraining
 • We control the knowledge base — no unverified internet data
 • Audit trail: every recommendation can be traced to source documents

CURRENT IMPLEMENTATION:

 1. Document Ingestion (rag/scripts/ingest_documents.py):
    • Reads PDF and TXT files from rag/data/raw/
    • PDF extraction via pdftotext (system utility)
    • Chunks text into 450-word segments
    • Outputs chunked JSON to rag/data/processed/

 2. RAG Service (ai-core/app/services/rag_service.py):
    • Loads knowledge_base.json (3 curated documents)
    • Uses sentence-transformers for text→vector encoding
    • FAISS index for fast cosine similarity search
    • Returns top-K most relevant chunks for a query

 3. Integration in Orchestrator:
    • After MCP data fetch, orchestrator queries RAG
    • Top chunks are injected into agent prompts as "verified context"
    • AI cites these sources in its response

PLANNED RAG UPGRADE:
 • Migrate from local JSON → Pinecone Vector Database
 • Expand knowledge base to 50+ veterinary documents
 • Add metadata filtering (disease type, species, region)
 • Implement chunk overlap for better context coverage
 • Add source citation in final output

12. COMPUTER VISION — CNN DISEASE DETECTION
================================================================================

ARCHITECTURE: Custom 4-Layer PoultryCNN

  Layer 1: Conv2d(3, 32, 3x3, padding=1) → ReLU → MaxPool2d(2)
  Layer 2: Conv2d(32, 64, 3x3, padding=1) → ReLU → MaxPool2d(2)
  Layer 3: Conv2d(64, 128, 3x3, padding=1) → ReLU → MaxPool2d(2)
  Layer 4: Conv2d(128, 256, 3x3, padding=1) → ReLU → AdaptiveAvgPool2d(1,1)
  Classifier: Flatten → Dropout(0.3) → Linear(256, num_classes)

  Input:  RGB image → resize to 128x128 → normalize to [-1, 1]
  Output: Softmax probability distribution over disease classes

TRAINING PIPELINE (ml/training/train_disease_cnn.py):
  • PoultryImageDataset: Custom PyTorch Dataset with balanced sampling
  • Supports: .jpg, .jpeg, .png, .bmp, .webp
  • Optimizer: Adam (lr=1e-3)
  • Loss: CrossEntropyLoss
  • Epochs: 12 (configurable)
  • Best model saved by validation accuracy
  • Exports: best_poultry_disease_cnn.pt + metrics.json

  CLI: python train_disease_cnn.py --data-dir ./dataset --epochs 12

INFERENCE PIPELINE (ai-core/app/services/vision_service.py):
  1. Receive base64-encoded image from frontend
  2. Decode → PIL Image → resize(128x128) → tensor
  3. Normalize: (pixel / 255 - 0.5) / 0.5
  4. Forward pass through loaded model
  5. Softmax → top prediction + confidence score
  6. Return: { predicted_class, confidence, all_probabilities }

FALLBACK MECHANISM:
  • If no image provided OR model file not found → falls back to
    symptom-based analysis via Disease MCP text matching
  • Ensures the system ALWAYS produces a response, even without vision

MODEL ARTIFACTS:
  • ml/training/artifacts-cpu-real/best_poultry_disease_cnn.pt — Production model
  • ml/training/artifacts-baseline/ — Baseline experiment
  • ml/training/artifacts-smoke*/ — Smoke test checkpoints
  • Each artifact directory includes metrics.json with full training history

13. COMPLETE DATA FLOW (Step-by-Step)
================================================================================

SCENARIO: Farmer uploads a photo of bloody droppings + types "birds not eating,
bloody stool, 21-day-old broilers, 28°C house temp, 65% humidity"

STEP 1: FRONTEND (React)
 → User opens Chatbot page → types symptoms → attaches photo
 → Chatbot.jsx calls diagnosisApi.uploadImage(formData)
 → FormData contains: image file + query text
 → Request: POST /api/diagnosis/upload (multipart)

STEP 2: BACKEND (Express.js)
 → diagnosis.ts receives multipart upload via Multer
 → Extracts image buffer → converts to base64
 → Validates request body with Zod schema
 → Builds payload: { query, image_base64, context: { ageInDays, temp, humidity } }
 → Forwards to AI Core: POST http://localhost:9000/analyze
 → Request: POST /analyze (JSON)

STEP 3: AI CORE — ORCHESTRATOR (FastAPI)
 → orchestrator.py receives AnalyzeRequest
 → PHASE 1: Vision Analysis
   → vision_service.predict(image_base64)
   → Decodes base64 → PIL Image → tensor → CNN forward pass
   → Result: { class: "Coccidiosis", confidence: 0.84 }
 → PHASE 2: LLM Symptom Summary
   → llm_service.summarize(symptoms_text)
   → OpenAI API call → "Bloody droppings and anorexia in 21-day broilers"
 → PHASE 3: Parallel MCP Data Fetch (via mcp_client.py)
   → Disease MCP:     GET http://localhost:8101/search?query=Coccidiosis&symptoms=bloody
   → Medicine MCP:    GET http://localhost:8102/recommend?disease=Coccidiosis
   → Feed MCP:        GET http://localhost:8103/recommend?ageInDays=21
   → Environment MCP: GET http://localhost:8104/recommend?ageInDays=21&temperatureC=28&humidityPercent=65
   → Memory MCP:      GET http://localhost:8106/history?farmId=farm_001
 → PHASE 4: RAG Knowledge Retrieval
   → rag_service.search("Coccidiosis treatment broiler")
   → Returns top-3 relevant chunks from veterinary knowledge base
 → PHASE 5: Agent Execution (Sequential)
   → Disease Agent: Fuses CNN result + MCP match + symptoms → disease insight
   → Medicine Agent: Formats MCP medicine data → treatment protocol
   → Feed Agent: Adjusts feed for disease stress → nutrition plan
   → Environment Agent: Evaluates housing conditions → climate advice
   → Safety Agent: POST http://localhost:8105/validate → checks contraindications
 → PHASE 6: Build Final Response
   → Combines all agent insights into structured FinalRecommendation
   → Computes accuracy = mean(all_agent_confidences)
   → Appends mandatory safety warnings to every section
   → Returns JSON to backend

STEP 4: BACKEND → FRONTEND
 → Backend receives AI Core response
 → Formats and returns to frontend
 → Chatbot.jsx renders: disease card, treatment plan, feed advice,
   environment warnings, safety alerts, confidence score

TOTAL LATENCY (Expected):
 • CNN Inference: ~50ms (CPU), ~10ms (GPU)
 • MCP Calls (parallel): ~20-50ms each
 • LLM Call: ~1-3 seconds
 • RAG Search: ~100ms
 • Agent Processing: ~200ms
 • Total: ~2-4 seconds end-to-end
